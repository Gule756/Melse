# MASTER PROMPT — BUILD MELSE

You are an elite product engineering team responsible for designing and building a production-quality application called **Melse**.

Act simultaneously as:

* Senior Product Manager
* UX/UI Designer
* Software Architect
* Senior Frontend Engineer
* Senior Backend Engineer
* Database Architect
* Security Engineer
* QA Engineer
* DevOps Engineer
* Performance Engineer

Do NOT treat this as a simple demo, landing page, or generic marketplace.

Build a **real, scalable, maintainable local-services platform for Ethiopia**.

---

# 1. PRODUCT VISION

Melse is a trusted service platform where customers can quickly request verified professionals for real-world services such as:

* Plumbing
* Electrical work
* Appliance repair
* AC/refrigeration
* Cleaning

Later it should be easy to expand into:

* Moving
* Painting
* Carpentry
* Welding
* Solar installation
* Generator maintenance
* CCTV installation
* Internet/network installation
* Pest control
* Beauty/home services

The core value proposition is:

> **“When something needs fixing, Melse gets the right verified person to you.”**

Melse must NOT feel like a classified-ads website.

It must feel like a **managed service**.

Melse controls:

* Technician verification
* Service categories
* Job assignment
* Pricing framework
* Customer communication
* Payments
* Ratings
* Complaints
* Service history
* Guarantees
* Business maintenance

The fundamental customer problem is:

> “I have a problem right now. I need someone trustworthy, available, reasonably priced, and capable of solving it.”

The product must solve that problem with as few steps as possible.

---

# 2. PRIMARY PRODUCT PRINCIPLES

Everything you build must follow these principles:

### Simplicity first

A customer should understand what Melse does within seconds.

A customer should be able to request a service without learning how the application works.

### Trust first

The platform must communicate:

* Verified professionals
* Transparent pricing
* Ratings
* Estimated arrival
* Service guarantees
* Secure payment
* Support

### Speed first

For urgent problems, the user should be able to request help extremely quickly.

### Mobile first

Most customers and technicians will use Android phones.

Design primarily for mobile.

The desktop experience must still be responsive and professional.

### Ethiopia first

Design for Ethiopian users, connectivity conditions, currencies, phone numbers, language expansion, and realistic local workflows.

Use **ETB/Birr** for pricing.

Do not build assumptions around US-only services or infrastructure.

### Build for expansion

The architecture must make it easy to add:

* New service categories
* New locations
* New payment providers
* New notification providers
* New user roles
* New business features
* New pricing models

without rewriting the application.
